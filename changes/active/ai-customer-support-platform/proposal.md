### Why（意图）

- 背景：当前项目是具备认证、用户管理和基础 CRUD 的全栈模板，业务辨识度不足，无法完整展示全栈岗位所需的复杂业务能力。
- 动机：将模板建设为可投递全栈岗位、并可在后续自然扩展 AI Copilot 的真实业务项目。

### What（范围）

#### 做什么

- [ ] 建设单工作空间客服工单平台，提供 Customer、Agent、Admin 三角色。
- [ ] Customer 创建、查看并回复自己的工单；Agent 接手和处理工单；Admin 管理用户、角色和全部工单。
- [ ] 完成工单创建、查询、接手、分派、状态流转、优先级、分类、公开回复和内部备注的业务闭环。
- [ ] 完成角色数据权限、操作记录、筛选分页及基础统计，并按后端、前端、联调测试的顺序开发。

#### 不做什么

- [ ] 一期不做多租户 Workspace，避免扩大权限和数据隔离范围。
- [ ] 一期不接入 AI Copilot、RAG、Tool Calling，待全栈业务稳定后单独立项。
- [ ] 一期不做实时聊天、邮件收件转工单、SLA、文件附件和复杂客服团队管理。

### 初步技术方向

沿用现有 FastAPI、React、TypeScript、PostgreSQL、OpenAPI 客户端和 Docker 工程基础，在现有认证与用户管理能力上扩展工单业务。

### 成功标准

- [ ] Customer 只能访问自己的工单；Agent 只能处理未分派或自己负责的工单；Admin 可以管理全部工单、用户和角色。
- [ ] Agent 可以接手未分派工单、发送公开回复、添加内部备注，以及修改自己负责工单的状态、优先级和分类。
- [ ] Agent 不能跨客服转派、管理用户或删除工单；上述管理操作由 Admin 负责。
- [ ] 工单从创建、接手或分派、处理、等待客户、解决到关闭形成可测试的完整闭环。
- [ ] 后端接口测试与前端关键流程 E2E 测试通过，项目可通过既有开发及 Docker 方式启动。
