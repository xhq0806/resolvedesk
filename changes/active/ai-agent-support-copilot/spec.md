# ResolveDesk 二期：AI Agent 与多租户客服工作台

## Why

一期已完成单 Workspace、三角色人工工单闭环，但当前用户、工单和权限都属于全局，无法展示多租户隔离、知识检索、Agent 工具编排和实时 AI 交互能力。

本期面向求职展示，建设一条可完整演示的 AI 客服主链路：用户进入 Workspace，上传知识库，配置模型，客户与 AI 流式对话，AI 检索知识并通过受控工具处理工单；人工可查看、接管和审计全过程。

## What

| 功能 | 验收标准 | 优先级 |
|---|---|---|
| Workspace 与成员 | 用户可加入多个 Workspace；创建者成为 Owner，成员角色为 `ADMIN`、`AGENT` 或 `CUSTOMER`；每个 Workspace 至少保留一个 Owner，所有业务资源只能在当前 Workspace 内访问 | P0 |
| 成员邀请与切换 | Owner/Admin 可邀请用户、撤销未接受邀请、移除成员和修改成员角色；用户可查看并切换所属 Workspace，切换后不得读取上一 Workspace 的缓存或资源 | P0 |
| 数据隔离与兼容 | 工单、消息、审计、知识文档、会话、附件、AI 配置和调用记录必须带 Workspace 归属；跨 Workspace 的读取、写入、工具调用和引用均返回统一拒绝 | P0 |
| AI Provider 配置 | Workspace Owner/Admin 可配置聊天模型和 Embedding 模型的 provider、base URL、模型名与 API Key，可测试连接；密钥只写入或替换，不回显原文 | P0 |
| 知识库 RAG | Owner/Admin 可上传受支持文档、查看处理状态、删除文档和重试失败任务；Agent 可浏览和检索，Customer 只能消费 AI 返回的授权来源；检索仅限当前 Workspace，并返回文档名、页码或段落位置等可点击来源 | P0 |
| 实时 AI 对话 | 用户可创建与 Workspace 或工单关联的会话；消息按流式事件显示文本、来源、工具调用、工具结果、完成和错误状态；用户可取消生成并继续对话 | P0 |
| Agent 自主回复 | 对启用 AI 的客户会话，AI 可直接发送公开工单回复并标记为 AI 生成；客户可看到 AI 身份，人工可接管、暂停或重新启用 AI | P0 |
| AI Agent 授权 | 每个 Workspace 拥有独立 AI Agent 执行主体；Owner/Admin 可逐项启用或停用工具权限，默认全部停用；AI 不继承客户角色，也不得超出配置权限 | P0 |
| Tool Calling | AI 只能调用已授权白名单工具；本期工具为读取当前工单、检索知识、更新状态/优先级/分类、发送公开回复和添加内部备注；每次执行仍须通过 Workspace、资源归属和状态机校验 | P0 |
| 调用审计与人工接管 | 每次模型请求、检索、工具调用、工具结果、AI 回复、失败和人工接管均可按会话查看；审计不记录 API Key，工具参数和结果按权限裁剪 | P0 |
| 文件附件 | 客户和客服可在允许的工单或会话中上传、下载和删除自己的附件；附件显示名称、类型、大小、上传者和时间，并遵守 Workspace 权限 | P1 |
| 演示验收链路 | 提供可重复的演示数据和 E2E 场景：上传 FAQ → 配置模型 → 提问并得到带引用回答 → AI 查询/修改工单 → AI 发送回复 → 人工接管 | P0 |

**不做的事：** 邮件收发转工单、SLA/自动升级、复杂客服团队/组长/技能路由、计费、生产级合规认证、超大规模队列、跨 Workspace 知识共享、AI 删除工单或管理成员、AI 修改模型和权限配置。

## How

### 1. 正常流程

1. 迁移后系统创建默认 Workspace；一期用户按原角色成为该 Workspace 成员，历史工单、消息和审计归入默认 Workspace。
2. 用户可创建 Workspace 并成为 Owner；Owner/Admin 邀请已有或新用户加入，指定成员角色；被邀请用户接受后才可访问该 Workspace。
3. 成员切换 Workspace；所有列表、详情、统计、查询缓存和 AI 会话上下文使用当前 Workspace。
4. Owner/Admin 配置聊天和 Embedding provider，测试连接成功后启用 AI；未配置或测试失败时，AI 入口显示不可用原因。
5. Owner/Admin 上传文档。文档经历 `PROCESSING`、`READY` 或 `FAILED` 状态；`READY` 文档才参与检索，失败文档可重试或删除。
6. 客户在工单详情开启 AI 会话并发送问题。系统流式返回状态、回答和来源；回答不足时明确说明知识库没有找到依据，不伪造来源。
7. Owner/Admin 为 Workspace AI Agent 逐项启用工具。AI 根据会话和检索结果调用已授权工具；每次调用先校验 Workspace、绑定工单、Agent 权限和状态机，再执行并回传结构化结果；失败时不伪造已完成。
8. AI 发送公开回复时，工单时间线显示 AI 作者和生成标记；状态、优先级或分类变化沿用一期状态机并写入审计。
9. 客服可停止 AI、接管会话、编辑后发送回复或重新启用 AI；接管后 AI 不再自动发送回复，直到明确恢复。
10. 用户上传附件后可在授权范围内下载；删除附件不删除消息或工单正文，相关删除事件进入审计。

#### 场景：跨 Workspace 访问被拒绝

- **Given** 用户属于 Workspace A 和 Workspace B，工单属于 A
- **When** 用户在当前 Workspace B 请求该工单、其附件、会话或调用记录
- **Then** 系统返回资源不存在或无权访问的统一错误，且不泄露标题、编号、来源或存在性

#### 场景：RAG 回答带来源

- **Given** 当前 Workspace 有两个 `READY` 文档，其中一个包含客户问题的答案
- **When** 客户发送问题并等待 AI 完成
- **Then** 回答正文显示可追溯来源；来源只包含当前 Workspace 文档，点击来源可定位到文档片段

#### 场景：知识不足时拒答

- **Given** 当前 Workspace 的 `READY` 文档不包含问题依据
- **When** 客户提问
- **Then** AI 明确表示无法从知识库确认答案，并提供转人工入口，不编造事实或来源

#### 场景：独立 AI Agent 执行授权工具

- **Given** 客户会话绑定工单 A，Owner 已授权 AI 修改分类和发送公开回复，未授权删除工单或管理成员
- **When** AI 修改工单 A 的分类并试图删除工单或管理成员
- **Then** 分类修改成功并写入 AI 审计；删除和成员操作在执行前被拒绝，其他数据不发生变化

#### 场景：AI 不得跳出绑定工单

- **Given** 客户会话绑定工单 A，同一 Workspace 还存在工单 B
- **When** AI 工具参数请求读取或修改工单 B
- **Then** 工具调用被拒绝，响应不泄露工单 B 的内容或存在性，拒绝记录进入调用审计

#### 场景：人工接管中断自主回复

- **Given** AI 正在流式生成或准备发送公开回复
- **When** 客服点击接管
- **Then** 当前生成被取消或标记为未发送，AI 不得发送该回复；客服可以继续编辑并人工发送

#### 场景：流式连接中断

- **Given** AI 已开始生成但客户端连接断开
- **When** 服务端检测到取消或超时
- **Then** 会话保存已确认的消息和失败状态，不保存为完整 AI 回复；用户可以重新发送，重复请求不会产生两条相同 AI 回复

### 2. 失败处理

| 失败场景 | 处理方式 |
|---|---|
| 邀请邮箱已是成员 | 拒绝并提示当前成员状态，不创建重复成员或邀请 |
| 尝试移除最后一个 Owner | 拒绝操作，Owner 数量保持至少一人 |
| Provider 鉴权、网络或格式错误 | AI 消息显示可理解的失败状态；记录 provider、状态和请求 ID，不记录密钥或完整敏感正文 |
| 文档类型不支持、超过大小或解析失败 | 文档进入 `FAILED`，返回具体原因，其他文档和会话不受影响 |
| 文档删除或重试期间被检索 | 只使用仍为 `READY` 的版本；不返回已删除文档来源 |
| Tool 参数缺失、越权或状态机非法 | 工具不执行，返回稳定错误码并写审计；不得部分更新工单 |
| AI 生成空内容或没有可靠来源 | 仅发送“无法从知识库确认并转人工”的安全回复，不输出推测性答案，并记录失败原因 |
| 附件下载者无权或附件不存在 | 返回统一资源错误，不泄露文件名、路径或 MIME 信息 |
| AI 会话对应工单已关闭 | 会话可读但不能写入工单、回复或工具变更 |
| 当前 Workspace 被停用或成员被移除 | 立即终止其 AI 流和写操作，已完成的审计与历史消息保留 |

### 3. 边界与约束

| 边界 | 说明 |
|---|---|
| Workspace 角色 | 角色属于成员关系，不再以全局 User 角色决定业务权限；Owner 具备 Workspace 管理权限，Admin 不能移除 Owner |
| AI 身份 | AI 是 Workspace 内的独立受控执行主体，不是登录用户；每次动作记录触发用户、AI Agent、会话和工具名 |
| AI 权限 | 工具默认全部停用，由 Owner/Admin 逐项授权；停用立即作用于新调用，进行中的调用须在写入前再次校验 |
| AI 自主范围 | 仅允许读取绑定工单、检索知识、修改非破坏性工单属性、发送公开回复和添加内部备注；不得删除工单、管理成员、修改 Provider 或操作未绑定工单 |
| 知识来源 | 仅使用当前 Workspace 的 `READY` 文档和当前用户可见的工单内容；文档中的指令视为不可信资料，不改变系统权限 |
| 文档格式 | 本期支持 PDF、DOCX、Markdown 和纯文本；单文件不超过 20 MB；超限或格式不支持必须在上传时拒绝 |
| 附件限制 | 单个附件不超过 10 MB；仅允许安全的常见文档、图片和文本类型；上传者、工单参与者和具备 Workspace 权限的客服按资源规则访问 |
| 消息限制 | 单条用户消息和 AI 回复均不超过 10,000 个字符；单个会话保留完整顺序和取消/失败状态 |
| 并发 | 同一会话同时只允许一个 AI 生成；用户取消、接管或新消息会终止旧生成 |
| 凭据 | API Key 只允许写入、替换和删除；任何 API、日志、前端状态、审计和 AI Prompt 都不得返回原文 |
| 一期兼容 | 既有登录、注册、工单状态机、公开回复、内部备注和管理员功能继续可用；没有 Workspace 上下文的旧请求必须被拒绝或引导选择 Workspace |

## Impact

- 用户与权限：全局 User 角色迁移为 Workspace Membership 角色，JWT/请求上下文增加当前 Workspace 选择。
- 工单领域：Ticket、Message、Audit 及一期查询、统计、状态机全部增加 Workspace 边界；AI 回复作为可审计的特殊作者类型进入时间线。
- AI 能力：新增 Provider 配置、知识文档、检索引用、会话、流式事件、工具执行和调用审计。
- 文件能力：新增知识库文件和工单/会话附件，涉及上传校验、存储访问和删除审计。
- 前端导航：新增 Workspace 切换、成员管理、AI 配置、知识库、AI 会话和附件状态；继续使用生成客户端并新增流式调用。
- 数据与部署：新增迁移和外部模型/向量服务配置；API Key 只在服务端处理，不进入前端构建产物或日志。

## 风险评估

| 风险 | 概率 | 影响 | 缓解措施 |
|---|---|---|---|
| Workspace 过滤遗漏导致跨租户泄漏 | 中 | 高 | 所有资源以 Workspace 上下文查询；增加跨租户 API、工具、引用和缓存测试 |
| Provider 或 RAG 外部调用失败 | 高 | 中 | 明确失败状态、超时、取消、重试边界和无来源拒答；不在事务内等待外部调用 |
| Prompt 注入诱导 Agent 越权 | 中 | 高 | 工具白名单、服务端权限重验、文档视为不可信、工具参数和结果审计 |
| 上传文件造成路径或内容安全问题 | 中 | 高 | 类型/大小/文件名校验、隔离存储、下载授权和恶意文件测试 |
| 流式断线产生重复或半条回复 | 中 | 中 | 会话状态机、取消信号、幂等键和断流回归场景 |

## 发布策略

- **发布方式**：先完成迁移和 Workspace 隔离，再以关闭 AI 的方式部署；Provider、RAG、流式聊天和工具调用按功能开关逐步启用。
- **回滚条件**：发现跨租户数据、密钥泄漏、工具越权、历史工单不可访问或一期回归失败时关闭二期开关并回滚对应迁移版本。
- **数据迁移**：创建默认 Workspace，将现有用户、工单、消息和审计回填到默认 Workspace；迁移需可重复执行并在无活跃 Owner/Admin 时失败。
- **版本策略**：OpenAPI 破坏性变化先同步后端契约和生成客户端；旧无 Workspace 请求在兼容窗口内返回选择 Workspace 的稳定错误，不静默使用错误租户。
